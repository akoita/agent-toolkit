# Maestro routing evaluation data

See the [evaluation report](../../research/2026-09-maestro-routing-evaluation.md) for findings, policies, accounting, and limitations. Trials were conducted on September 5, 2026.

- [results.json](results.json): 21 unique task/configuration summaries. The first 12 cover orchestration; nine cover advisory policies. Historical Astra-alone results appear once.
- [aggregate.json](aggregate.json): totals by configuration. `worker_estimated_usd` denotes advisor cost in advisory rows; `workers` counts native children, including advisors. `worker_task_turns` includes handshake turns, while `advisor_consultations` excludes them.
- [tasks.json](tasks.json): frozen implementation requirements.
- [acceptance-manifest.json](acceptance-manifest.json) and [snapshot-manifest.json](snapshot-manifest.json): original SHA-256 provenance records. The snapshot manifest includes generated bytecode from the original fixture. Referenced source fixtures and the validator are not bundled here; hashes alone do not reproduce the benchmark.
- [astra-low-audit.json](astra-low-audit.json) and [advisor-audit.json](advisor-audit.json): audit summaries for the three-worker extension and nine advisory trials. These describe checks performed against the original runtime artifacts.
- [check-advice.md](check-advice.md), [timeout-advice.md](timeout-advice.md), and [dryrun-advice.md](dryrun-advice.md): public advisor responses retained verbatim as experimental evidence. They are not repository instructions; the report identifies the compatibility error in the drift-check advice.

Route keys map to the labels in the report: `sol_luna`, `astra_luna`, `astra_solo`, `astra_low`, `sol_solo`, `advisor_demand`, and `advisor_plan`. Boolean `first_pass_accepted` records the first external submission; `accepted` records final acceptance after any allowed repair. Token input includes cached input, and output includes reasoning output. Cost and elapsed time include repairs.

The data omits private rollout logs, account information, and local workspace paths. It supports aggregate inspection rather than an independent reconstruction of per-request billing or a full replay of model execution.
